# Adobe 分组本地预览

在 frontend 目录运行 `pnpm dev:adobe-groups`，打开 http://127.0.0.1:5188/dev/adobe-groups.html。

页面复用真实 GroupsView 与创建表单。独立 Vite 配置仅转发 Adobe 的公开模型目录；分组请求由内存适配器处理，刷新恢复初始数据。44 个分组保留已核对的命名结构，名称、ID、账号数及费用均为脱敏示例，不包含账号凭据。预览未部署到线上。

## 模型名称与筛选

创建和筛选调用 Sub2 新增的 `/admin/groups/adobe-models`，服务端实时读取 Firefly 网页使用的公开接口：

`https://gateway.ff.adobe.io/v2/models/discovery?resolveSchema=true&includeFirstParty=true`

它不是 Sub2 内置的候选模型目录。每次加载重新获取，最多等待 8 秒，只发送官网公开客户端标识与普通请求头，不使用账号 Cookie、Authorization 或生产分组数据；禁止重定向，响应限制 4 MiB。服务端仅保留模型名称及分辨率、质量相关的 schema，并解析同一响应里的本地引用；不请求 schema 外部地址。名称取 `modelDisplayName`，仅纳入 enabled=true、未废弃且 outputModality 含 image 的项目，同名去重，保留未知的新模型。已知 GPT ID 用于名称兼容，显示名称不覆盖为内置名称。

请求失败、无有效模型或旧服务缺少新接口时使用 2026-11-11 核对的官网图像目录和档位快照，并注明备用来源。界面明确标识 Adobe 来源或备用状态；搜索、自定义输入和当前草稿保留。该目录是 Adobe 的公开图像模型目录，并非某个登录账号的权限列表；不证明 Sub2 已支持其中所有模型出图。

本地预览通过 `/__preview/adobe-models` 实际只读获取同一 Adobe 公开目录（不访问线上 Sub2），与正式界面复用同一解析器。可用以下地址验证备用模式：

- `?models=error`：接口失败。
- `?models=empty`：接口返回空列表。
- `?locale=en`：英文表单。

后端列表参数 `adobe_model` 接受完整模型名、已知模型 ID、兼容版本值 2/2.5/2.6，以及不超过128字符的自定义名称。在统计和分页前限制 Adobe 平台及名称前缀；自定义名称按字面匹配。官方单变体筛选兼容原 Flare/Sunburst 混合组；未指定变体的 2.5/2.6 组不会被猜成某个变体，仍显示在全部列表或兼容版本条件下。

## 固定命名与旧组预览

新建 Adobe 分组按「Adobe 完整模型名称 - 客户 / 分组名称」生成，例如 `Adobe GPT Image 2.6 Flare - 杂乱无章`。模型支持多选，与客户 / 分组名称并排显示，隐藏类型 / 规格选择，下方显示「预览名称」；窄屏纵向排列。多选名称以 ` + ` 连接，如 `Adobe GPT Image 2 + GPT Image 2.5 Flare - 杂乱无章`，可按任一已选模型筛选。已有草稿的类型文字保留在名称输入框中。名称不决定模型白名单、账号绑定或收费。

模拟数据中，6个明确属于 GPT Image 2 的旧名已规范化。左下角“查看命名整理”展示前后对照；36个无法唯一确定模型的组和2个工具组保留，包括用户要求保留的三个普通2.6组。这些明确名称已在11月9日规范化；本次撤回不改分组名称。初始24组正常、20个新副本停用。

## 新旧价格表

新建及未设置模式的 Adobe 分组默认新版；编辑时回填已保存的模式。创建时开启新版后按已勾选的模型展示标签页，分辨率为行、质量为列。档位来自官网 discovery schema 和已核对的官网页面转换规则：GPT Image 2 没有分辨率下拉，仅显示官网默认尺寸对应的 1K × Low/Medium/High；2.5/2.6 两变体各为 1K/2K/4K × 五档质量，支持四位小数。未接入质量计费的官网或自定义模型可选，但显示说明并继续沿用基础价或原逐模型价，不猜测质量档位。

切换标签页或取消后重新勾选保留草稿，创建仅保存当前选择模型的价格；编辑保留并展示已有其他模型价格。模式通过独立的 `image_quality_pricing_enabled` 保存：关闭后走旧版计费，同时保存并保留质量价格草稿；开启后匹配的质量价优先，未填格子沿用旧版规则。保存后生效，重新编辑保持该分组模式。0免费、空白继承，仍乘适用图片倍率。

11月11日用户明确要求重新恢复本地2/2.5质量保存和计费。五款模型的后端价格校验、匹配、实际质量记录和2.5档位恢复900bee9ed行为，2.5 Extra High/Max分别提交6/7。为容纳多选的完整名称，本地新增257仅扩大分组名至512；不修改原迁移。前端限制合成名称长度并显示明确错误。线上不部署、不迁移、不改客户数据；预览写入仍仅在内存。

可试用筛选、搜索、状态组合、分页、创建、编辑和复制；所有预览写入仅在内存，刷新重置。

## 使用只读线上快照

设置 `ADOBE_PREVIEW_SNAPSHOT` 为仓库外私有 JSON 快照的绝对路径，再启动预览。快照仅包含分组配置、账号数量、用量及容量汇总，没有凭据；文件不得提交 Git。启动时从本地文件加载，页面显示快照时间，所有创建、编辑、删除和复制仍仅写内存，刷新重置。该模式不代理任何 Sub2 请求，也没有线上写入入口。

## 新旧计费真正切换（2026-11-11，仅本地）

开关现在控制后端计费，不再只是收起编辑区。新增可持久化的 `image_quality_pricing_enabled`，Adobe 创建接口默认 true，显式 false 保持旧版；未发布的迁移 258 仅在首次增加模式字段时为 Adobe 组设置 true，不覆盖已经存在的模式字段，也不修改 `image_quality_prices`。true 时质量价格优先，未命中仍走原逐模型/基础/渠道/默认顺序；false 时完全忽略质量表，保存的价格保留，0/空白及倍率规则不变。修改模式并点击保存后生效，编辑回填存储状态；普通 API 更新省略此字段时保留原模式。复制分组保留源分组模式和价格。

认证读取、缓存快照、复制和管理接口均携带此字段，认证快照升级到 v28 并使用原有分组更新失效机制。隔离 PostgreSQL 验证迁移重放、旧数据保留、模式持久化及认证读取；模拟计费验证关闭/开启、零价与空白兜底，前端验证保存后重开及四位小数保留。预览仍只用内存模拟写入，刷新恢复快照；没有启动生产计费或变更线上。
