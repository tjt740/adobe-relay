## 功能与保存规则

- 删除固定 8 条链接上限。链接文本最多 64 KiB，重复链接按首次出现顺序合并。单条订阅仍最多 8 MiB，合并节点仍最多 512 个；超出节点预算时拒绝本次操作并保留原配置。预览 JSON 请求最多 128 KiB，导入 JSON 最多 512 KiB，为原节点选择及新增来源映射留出空间。
- 前台预览、导入重取和后台刷新共享最多 4 路拉取，每条获得执行位置后限时 8 秒，使用固定 worker 数量；闲置连接总池最多 8 个，闲置一分钟关闭，避免链接增多后连接长期积累。预览总预算 35 秒。按输入顺序显示结果，不按网络完成顺序改变节点名称。
- 每个来源独立报告成功、失败或本轮未完成。正常来源继续更新；失败／未完成来源的已有启用节点、代理 ID、端口、入口密码和账号绑定保留，预览中禁止取消这些保留节点。历史停用节点也不会因获取失败而重新启用。全部来源失败时禁止保存。
- 保存会重新读取订阅。预览成功、保存时失败的新来源按其来源标识跳过新节点，其他成功来源继续；该来源已有节点依然保留。成功来源的节点确实发生变化时，原重新预览校验仍保留。旧 API 调用者不提供来源映射时继续采用保守校验。
- 同一来源与原始节点名称用于稳定匹配；调整链接顺序不会把不同来源的同名节点交换绑定。名称碰撞时加短来源标记，继续遵守既有名称长度预算。
- 主动删除订阅链接、取消成功来源的节点选择，继续执行原代理移除和账号暂停流程。取消全选仅删除成功读取来源的节点。至少保留一行输入；全部留空仍沿用原保存链接，清空节点采用原预览后取消全选入口。

## 后台刷新

按最近观察时间从旧到新处理到期来源，后台每轮网络预算 20 秒，保留正常刷新和失败退避间隔。没有完成的来源不增加失败次数、不更新时间，下一轮继续优先处理；单条失败不取消其他工作。

网络访问期间使用专用连接上的 advisory lock 选主，不开启 SQL 事务。完成后再在短事务中锁定配置行，复核版本与链接未变，仅保存已经完成的观察。单条超时和批次预算耗尽分别处理；批次耗尽不会丢弃其他已完成结果。释放锁失败时丢弃对应连接，避免带锁回到连接池。

健康观察和新增原始节点名称不进入运行时标记，因此不会仅因监控记录变化重新加载 Mihomo。原流量耗尽、到期证据和恢复条件保留。
