# 401 账号修复操作归档

这些文件记录 2026-10-20 用户明确要求修复线上 401 时执行的操作。它们不属于应用请求路径。`workflow-archive.yml` 是当时操作分支的副本，放在发布文档目录，不启用新的 GitHub 工作流；正式发布工作流保持原样。

初始范围由主服务器私有盘点快照固定，362 个历史登录上限账号中仅处理 181 个未暂停账号。先验证当前认证，确认失效才通过正常登录协调器手动授权；3 个先行试修账号在后续批处理中复用其新会话。本批次共恢复 181 个账号，每个最多发起一个手动授权任务；没有人为重置自动登录预算。来源指纹、关联邮箱、原组织身份、过期与暂停保护保留，资料补全及修改密码路径在修复进程中禁用，代理和可靠同步继续沿用原流程。

`adobe-401-batch-v2.py`、`adobe-401-host-worker.py` 和 `adobe-401-pilot.py` 依赖主服务器私有快照与持久标记；代码不包含账号明细、密码、Cookie 或 Token。已有授权标记防止重放，包括结果未知的任务。后续需要授权时使用正常手动登录入口，保留历史标记，不通过删除标记重复运行旧任务。

`adobe-401-primary-diagnostic.py` 对原主号做实际额度检查及组织身份比对，只输出分类与汇总；`adobe-401-primary-repair.py` 在来源、暂停与过期保护后复用正常登录协调器，另行执行一次原主号的手动授权，沿用同一个持久授权标记，不重置自动次数。详细结果只留在服务器私有文件。原主号不在初始 181 个批次范围内。

`adobe-401-control.py` 仅控制此次已审核镜像的准备、滚动发布、观察与核验。实际应用为 `8241adfe9a5850095ef6ea06ab2e9c2f991b0f48`；对应操作脚本见相邻 `../adobe-401-repair-20261020/`。代码回退始终保留当前凭据、业务数据、人工状态、代理与配置，不恢复旧数据库。原始日志、输入和操作结果仅留在主服务器权限受限的审计目录。

重复最终核验前，将已有汇总证据移至带 UTC 时间戳的 `verification-history/`，再重新读取现网业务与凭据、校验原主号额度。历史文件保留，既不覆盖旧证据，也不因已有只写一次文件而跳过实际复查。
