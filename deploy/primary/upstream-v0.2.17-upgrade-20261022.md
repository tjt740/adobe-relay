## 本站兼容性处理

- 新平台目录补回 Adobe / Kiro，保留其专属网关，不将 Adobe Cookie 或 Kiro OAuth 误送到 OpenAI / Anthropic 上游。沿用原有快照及渠道匹配的平台顺序。
- 保留 Adobe 模型目录、别名、共享图片模型归属、独立检测与人工暂停保护；合入上游组合路由防止 OAuth 凭据误投的修复。
- 保留 API Key 返回、Okad 联动依赖注入、代理故障切换、手动代理修改保护和默认 300 条分页。上游新控件接入本站共享 Select；新增供应商与 Adobe / Kiro 继续可选。
- 上游新增的在途余额预留在本站默认关闭，密钥创建数量/频率的新限制默认设为 0（不额外限制）；仍可显式配置启用。避免旧配置缺省时自动改变现有准入、并发和密钥创建行为；原有余额、账号/用户并发及业务配额不变。
- 保留 Kiro 本地 count_tokens、原始用户搜索词及缓存计账。搜索失败不推进缓存计账状态；新增回归覆盖该边界。
- 从已合并 schema 重新生成 Ent 与 Wire，不手工保留过期字段索引或缺失依赖。
- Adobe 专属实现、Okad 专属实现、Clash 与 proxyfailover 源码没有被上游替换；原主服务器发布工作流和 `release.sh` 保持。
