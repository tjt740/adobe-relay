# Adobe 会话续期修正（2026-10-20）

Cookie 换 token 会收到多个 `Set-Cookie`，其中包括轮换后的 IMS 会话。原客户端将多值响应头折为第一项，刷新路径只持久化 token，常驻客户端的 Cookie jar 还可能向显式 Cookie 请求追加另一份 `ims_sid`。重新获取 Cookie 当时可用，并不能证明稍后的刷新还在使用同一份会话。

“重新校验”查询此前会重复使用已被拒绝但尚未到期的 token，业务入口也只会清空被拒绝的 token 并换号，原请求没有机会在会话续期后成功。现在额度查询 401 可通过相同的 Cookie 恢复一次；出图只对明确在提交前被 Adobe 拒绝的那张图片续期并重试一次；已受理、轮询、下载和结果未知的请求不重新生成，多图中已经成功的兄弟任务不重复提交。Cookie 续期不调用 Okad 登录，不增加验证码预算，账户、组织、代理、人工暂停变化会停止旧请求的恢复。

此次修正完整保留响应 Cookie，按 Adobe IMS 的域、路径、过期及删除规则合并；显式会话请求使用独立的无自动 jar 客户端，保持其他 API 的原有 Cookie 行为。更新后的会话与 token 原子写入，绑定导入 Cookie 的 SHA-256，下一次刷新优先使用它。导入 Cookie 保持原值，兼容 Okad 来源版本、重复投递和检测任务标识；新导入会清理旧运行会话，手工替换 Cookie 后旧续期结果失效。

保存时比较来源 Cookie、运行会话及绑定、代理和代理更新时间；旧响应不能覆盖更新的会话，延迟的鉴权失败也不能隔离新的会话。原有人工暂停、模型映射、额度与限流处理保留，不增加自动登录次数。额度查询暂时失败时仍保留已经由 IMS 确认的 Cookie 续期，但不发布未验证 token；身份不匹配时不接受结果。

已增加逐图单次续期、批量兄弟任务不重放、受理与取消保护、组织身份及人工暂停变化，以及客户端 Cookie 轮换、重复 Cookie、删除与域/路径规则、来源替换、后续额度失败，以及 PostgreSQL 原子合并与旧响应保护回归。上线前要求相关测试、正式构建和隔离的新旧 Cookie 空闲对照通过；不能仅凭即时成功声称根除了全部上游 401。

仅在主服务器沿用现行发布锁、受控滚动、排空、备份与代码回退流程。保留当前所有数据、人工状态、分组 2/7 操作、代理分配、54 GiB / Go 43008 MiB / 图片 37.8 GiB / GOMAXPROCS=16 / CPU shares 4096、Okad 3 GiB 及实际运行镜像、配置、SMTP、告警和其他服务。无数据库迁移，不恢复旧数据库。实际发布证据、镜像、备份与回退条件在完成后补记。
