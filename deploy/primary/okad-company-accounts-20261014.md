# Okad 公司账号筛选（2026-10-14，未发布）

## 范围

Sub2 账号管理新增「全部账号归属 / Okad · 公司 / Okad · 非公司 / Okad · 待识别」。公司账号名称旁显示绿色「公司」tag；现有状态 tag 的文字、颜色、条件保持原样。

公司定义与 Okad 外部子号列表一致：`otp_mode != manual`，没有 `mail_url`，也没有完整的 `refresh_token + client_id` 收信配置，即通过公司取信服务获取验证码。不是按邮箱域名、Adobe 企业 Profile 或订阅权益推断。号池来源没有该公司标记。

缺少标记、来源不一致、邮箱变更的已导入账号归为「待识别」；未从 Okad 导入的账号不会因此被判为非公司。分页、全选、导出、批量编辑和实时列表更新采用同一分类条件。公司筛选先限制到 Adobe OAuth，再按既有筛选管线分页。

## 同步与兼容

- Sub2 存储独立 `extra.okad_account`：`issuer / source_key / email / is_company`。无数据库迁移。
- 专用联动能力新增 `account_metadata`，库存新增 `imported_email / account_metadata`。
- 独立 `POST /api/v1/integrations/okad/account-metadata` 使用现有专用鉴权，每批最多 200 条，只原子更新分类及更新时间。数据库核对当前邮箱、导入标记、来源和实例，拒绝覆盖其他来源、平台、类型或已删除账号。
- 已配置可靠联动时，Okad 在原约 30 秒库存核对中自动补齐已有账号，并跟随 Okad 公司标记变化更新。无凭据投递任务也能补齐；数据未变化时不写入。旧 Sub2 未声明能力则跳过。
- 无来源键的旧导入必须已有导入邮箱标记，且 Okad 侧同邮箱来源唯一；多个来源同邮箱不猜测归属。已可靠关联的账号按来源键核对，不受另一同邮箱来源干扰。
- 新可靠导入直接带上分类；旧推送入口在已配置 Okad 实例标识时也携带分类。未配置实例标识的旧入口保持兼容，类型保留待识别，待配置可靠联动后补齐。
- 分类同步不发送 Cookie/Token，不清除 Token 缓存，不调用 Adobe，不排队检测、登录、恢复或调度任务。读取/同步失败保留已有标记，下一次重试，不以失败推断非公司。
