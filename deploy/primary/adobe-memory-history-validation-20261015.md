# 12 GiB 内存调整的下午流量验证

应用版本：`f16489d9a0ed4f9b4ebcd78816e6bb157d582fe8`（PR #62）。本记录与新增测试仅补充验证，不产生另一次应用发布。

## 变更边界

本次用户明确要求主服务器容器上限 12 GiB、Go 目标 9216 MiB，不新增排队，并保留原配置、功能和同图下载重试。正式应用变更及回滚见 `adobe-memory-adaptive-20261015.md`。只允许发布到 `173.234.15.150` / `https://creative.cheap`。

代码审核确认：读取/解压时先申请容量，解析与审核后释放临时额度；最终保留三倍输入字节及每张输出图 32 MiB。容量不足立即 429，多图扩容发生在提交生成之前，已接收的脱离客户端任务仍持有容量。图片池为 Go 目标的三分之二，即 6 GiB。

原下载逻辑继续对同一个签名 URL 执行 GET，失败后切换已有备用出口。已提交任务的轮询/下载重试耗尽后停止换号，避免重新生成另一张图片。相关 Adobe 下载/备用出口/错误分类回归通过。

## 历史数据和测试方法

- 采样窗口为北京时间 2026-10-15 16:50:02–16:59:36，共 3,075 次请求；这批记录包含客户端重试，不能视为 3,075 个独立订单。
- 只读取日志的时间、大小、路径、图片数量和耗时元数据；测试内容为合成字节，不读取用户图片，不连接 Adobe 或生产数据库，不发送邮件。
- 日志大小来自规范化审核 JSON，不是 HTTP `Content-Length`。本测试将其作为 multipart 图片字节大小，故并非逐字节原请求回放。审核体积中位数 1.33 MiB，P95 为 11.44 MiB，P99 为 23.41 MiB，最大 46.88 MiB。
- 2,768 条能匹配结束时间；其余 307 条按 180 秒占用估算。整段回放将到达间隔和占用时间都缩为 0.05 倍。压缩时间会改变 CPU 与调度开销占比，结果用于比较和压力验证，不作为线上吞吐承诺。
- 走实际请求读取、multipart 解析、审核 JSON 和额度调整；每十条中一条使用未知长度。每个接入请求生成 4 MiB 合成输出，并实际完成 Base64 和 JSON 编码。突发测试令所有输出同时驻留，覆盖集中完成时的内存增长。
- Linux 测试容器禁网络、只读、4 CPU；**测试硬上限为 6 GiB**、Go 目标 9216 MiB，以相同的 6 GiB 逻辑容量池在更严格的物理上限下验证。此临时测试配置不写入生产。正式生产配置仍为 12 / 9 GiB。执行期间持有 Sub2 发布锁，主机可用内存低于 2 GiB 时只终止测试容器。

## 结果

| Linux 负载 | 接入 | 立即 429 | 峰值在途 |
| --- | ---: | ---: | ---: |
| 同时进入 100 条 | 100 | 0 | 100 |
| 同时进入 200 条 | 147 | 53 | 147 |
| 同时进入 300 条 | 130 | 170 | 130 |
| 同时进入 400 条 | 142 | 258 | 142 |
| 按时间比例回放全部 3,075 条 | 1,261 | 1,814 | 164 |

突发四组测试的 cgroup 峰值为 3,384,451,072 字节（约 3.15 GiB）；整段回放峰值为 1,250,312,192 字节（约 1.16 GiB）。退出码均为 0，`oom=0`、`oom_kill=0`，容量和在途计数全部归零。测试前后生产 Sub2 与 Okad 容器身份、健康状态、重启计数和资源设置一致。突发组主机最低可用内存约 10.74 GiB，整段约 12.83 GiB。

本地整段回放接入 1,314、拒绝 1,761、峰值在途 165；差别体现调度和运行环境影响。按旧版 8 / 6 GiB 配置及旧算法计算同一批占用，预计接入约 378–380 条；这是容量模拟，不是旧应用实跑。Linux 新版接入数约为该估算的 3.3 倍。

**结论：当前负载下内存验证通过，过早拒绝有明显缓解，但历史高峰仍存在大量容量拒绝。不能宣称支持 400 个请求全部同时处理或消除了所有 429。** 固定输出大小的测试不证明任意大输出、任意多图及全部转换格式的绝对内存安全；上游 429、账号和用户并发限制也不由此次内存扩容消除。

本地额外将输出增大到每张 8 MiB，100/200/300/400 突发组仍全部完成；该项是本地补测，不混作 Linux cgroup 峰值结果。

## 复现与审计

测试入口 `backend/internal/server/middleware/image_memory_history_test.go`，默认跳过，必须显式传入脱敏轨迹及 Go 目标，并在隔离环境运行：

```sh
ADOBE_HISTORY_TRACE=/trace.json GOMEMLIMIT=9216MiB \
  go test ./internal/server/middleware -run '^TestImageMemoryHistoricalBurst$' -count=1 -timeout=4m -v
ADOBE_HISTORY_TRACE=/trace.json GOMEMLIMIT=9216MiB ADOBE_HISTORY_PACED=1 \
  go test ./internal/server/middleware -run '^TestImageMemoryHistoricalBurst$' -count=1 -timeout=4m -v
```

在 backend 目录执行。该测试主动制造 GiB 级内存占用，不纳入普通单元测试的默认运行。`ADOBE_HISTORY_OUTPUT_MIB` 控制每张合成输出大小，默认 4。

服务器独立审计目录 `/opt/adobe-relay/releases/adobe-memory-history-validation-20261015/` 保存脱敏轨迹、Linux 测试二进制、两组完整日志和 `linux-validation.json`。测试二进制 SHA256：`e08955ba29443c54a161d54383c439c02b2f9f70463c9556994caf6e3b9981b7`。生产发布、配置保留和回滚审计沿用 `/opt/adobe-relay/releases/adobe-memory-adaptive-20261015/`。
